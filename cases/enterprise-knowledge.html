01 / 背景

企业里最难复用的往往是已经做过的项目

售前方案、招投标文件、产品参数和项目资料长期分散在不同文件夹、不同项目和不同同事手里。资料并不是不存在，而是难以快速找到、判断是否适用，更难直接进入下一次交付。这个项目的目标不是简单“把文件放到一个地方”，而是让知识拥有清晰的结构、检索入口和使用路径。

01 / 现状

资料分散

历史项目、产品资料、技术方案和交付文件缺乏统一组织方式。

02 / 成本

查找与整理慢

每次项目都要重新翻找资料、确认版本，再手工拼装内容。

03 / 目标

知识进入业务

让资料可以被检索、引用、调用，并服务于方案和招投标文档生产。

02 / 信息架构

用两个维度组织知识让找到变成能用

资料归集

收集历史方案、项目文档、产品资料和招投标内容，明确来源与适用范围。

03 / 我的工作

我关注的不只是建库还包括知识如何被业务使用

01

设计分类与检索

围绕售前和招投标的真实提问，建立项目 / 产品双维度组织方式，降低定位资料的成本。

02

衔接 ERP 数据

推进企业结构化业务数据与 Agent 工具对接，将业务数据变成可以查询和调用的能力。

03

连接文档生产

让知识库不止承担问答，还能服务于方案、招投标文件和相关业务文档的辅助生成。

04 / 项目结果

把分散资料变成可以继续增长的业务资产

  • 完成售前方案知识库和招投标知识库建设，将项目、产品及方案资料转化为可检索资产。
  • 形成项目 / 产品双维度检索体系，降低历史资料查找和信息整理成本。
  • 实现知识库与 Agent 工具联动，可直接服务于售前方案、招投标文件等业务文档制作。
  • 推进 ERP + Agent + 企业知识库能力衔接，为后续业务问答、智能检索和流程自动化提供数据基础。
